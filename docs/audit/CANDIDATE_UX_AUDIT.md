# Candidate UX/UI Audit

Review references include the local quality standard, Nielsen heuristics, the fetched Web Interface Guidelines, and static UI review. Manual viewport/browser verification is still required for visual issues.

| ID | Screen | Component | Current behavior | UX problem | Evidence | Recommended behavior | Priority | Acceptance criteria |
|---|---|---|---|---|---|---|---|---|
| UX-001 | Candidate profile | Profile form | Candidate edits profile sections and clicks save. | No unsaved-change warning; accidental navigation loses edits. | `frontend/src/App.tsx:2833-3049`; no dirty guard found. | Track dirty state and warn on route/browser navigation. | P2 | Back/refresh with unsaved edits prompts or preserves draft. |
| UX-002 | Candidate profile | Education/experience/projects/certs | Same generic four fields for every section. | Users cannot enter expected section-specific data such as degree, start/end dates, current job, credential URL. | `frontend/src/App.tsx:2986-3038`. | Use section-specific forms with date controls and relevant fields. | P1 | Each section captures structured, understandable fields with inline validation. |
| UX-003 | Candidate profile | Skills | Comma-separated text input. | Error-prone on mobile and creates inconsistent data; no autocomplete or visible tokens. | `frontend/src/App.tsx:2959-2964`, `2850`. | Use tokenized skill picker/autocomplete with removable chips. | P2 | Candidate can add/remove skills without comma syntax; duplicates are prevented. |
| UX-004 | Jobs | Search/filter panel | Filters are submitted manually and URL persists state. | Good URL state, but no active filter chips/result count context beyond list count; category filter is missing. | `frontend/src/App.tsx:1906-1956`, `1963-2069`. | Show active filter summary, clear individual filters, add category if supported. | P2 | Active filters visible and removable; category URL/filter works. |
| UX-005 | Jobs | Pagination | Previous/next only, page number visible. | No direct first/last/page jump; no page size control. | `frontend/src/App.tsx:2125-2134`. | Add numbered pagination or load-more depending dataset. | P3 | Candidate can navigate to specific pages for large result sets. |
| UX-006 | Candidate lists | Saved jobs/applications/notifications/sessions | Lists fetch and render all returned items. | No candidate-visible pagination, filtering, sorting, or search for growing personal histories. | `frontend/src/App.tsx:3625-4155`, `4444-4739`. | Add pagination/search/status filters where lists can grow. | P1 | Large candidate histories remain scannable and performant. |
| UX-007 | Job detail | Apply action | Apply modal blocks unless CV/location/checkboxes are selected. | AI consent/policy checkboxes gate submission but are not persisted; user trust issue. | `frontend/src/App.tsx:337-389`, `539-553`, `ApplicationSubmitRequest.java:6-10`. | Persist consent or remove gating; explain data usage in linked policy. | P1 | Consent state is auditable or not required to submit. |
| UX-008 | Job detail | Save action | Save button uses emoji bookmark text and optimistic toggle. | Emoji-as-icon styling is inconsistent with professional UI guidelines and may be read awkwardly by assistive tech. | `frontend/src/App.tsx:2433`, `frontend/src/styles/global.css:3065-3070`. | Use icon component/SVG with accessible text. | P3 | Save button has stable icon, accessible name, and clear saved state. |
| UX-009 | Apply modal | File upload | Drop/upload area supports click/keyboard and PDF validation. | Good start, but upload progress is not shown for slow connections. | `frontend/src/App.tsx:395-553`. | Show upload progress or distinct "uploading CV" step. | P2 | Slow upload indicates progress and prevents duplicate submit. |
| UX-010 | Apply modal | Cover letter | Character count shown. | Textarea lacks `maxLength`; over-limit is only rejected after submit. | `frontend/src/App.tsx:523-528`, `ApplicationService.java:280-283`. | Enforce `maxLength=2000` and inline error. | P2 | User cannot submit over-limit cover letter. |
| UX-011 | CV page | Delete dialogs | Uploaded CV and builder CV delete confirmations exist. | Dialogs rely on backdrop/mouse events and do not trap/restore focus. | `frontend/src/App.tsx:251-303`, `3597-3618`. | Use accessible modal primitive with focus trap, Escape, restore focus. | P1 | Keyboard-only users can operate dialogs predictably. |
| UX-012 | Account page | Deactivate account | Candidate enters current password and submits. | Sensitive/destructive action exists, but no explicit second confirmation beyond password field. | `frontend/src/App.tsx:3305-3321`. | Add confirmation modal or typed confirmation. | P2 | Accidental submit is prevented and recovery/impact is explained. |
| UX-013 | Notifications | Mark read | Each notification can be marked read and all can be marked read. | Failure handling is weak; action reloads list but does not show retry/error. | `frontend/src/App.tsx:4063-4155`. | Optimistic update with rollback and toast/status. | P2 | Failed mark-read leaves item unread and shows retry. |
| UX-014 | Application detail | Interview/offer actions | Candidate can confirm/reschedule/respond. | Response controls appear inline in detail; state persistence for open modal/textarea is not URL-backed and can be lost. | `frontend/src/App.tsx:3747-4039`. | Preserve modal draft or warn on close/navigation. | P2 | Candidate draft note survives accidental close/refresh or warns. |
| UX-015 | AI interview | Tabs/modes | `activeTab`, `questionMode`, selected question set are local state. | Browser Back/refresh loses tab/mode configuration. | `frontend/src/App.tsx:4449-4455`, `4561-4718`. | Sync tab/mode/session to URL query params or local draft. | P2 | Refresh/back returns to same AI tab/mode/session. |
| UX-016 | AI interview | Long operations | Busy text appears for STT/evaluation/summary. | Long AI operations lack progress/timeout/retry affordance until failure. | `frontend/src/App.tsx:4821-4917`, `5099-5108`. | Show cancellable/progressive status and expected time. | P2 | Candidate sees elapsed/expected time and retry path. |
| UX-017 | AI interview | Finish | Candidate can finish from current question. | UI can allow finish after all skips, then backend rejects because no evaluable answers. | `frontend/src/App.tsx:5087-5099`, `AiInterviewService.java:299-302`. | Disable finish or explain minimum answer requirement. | P2 | Finish is only enabled when completion rules are satisfied. |
| UX-018 | AI interview | Transcript | Manual transcript can be edited; hands-free transcript is read-only. | Editing model differs by mode and unsaved transcript can be lost. | `frontend/src/App.tsx:5033-5040`, `5067-5073`. | Clarify/edit model and persist draft transcript. | P1 | Unsaved transcript is not lost on refresh/back. |
| UX-019 | AI interview | Fallback result | Fallback summary and feedback are labeled. | Numeric score still displays, which can make fallback feel official. | `frontend/src/App.tsx:4953-4965`, `5160-5168`. | Show fallback as "not fully evaluated" and de-emphasize/withhold score. | P1 | Fallback state cannot be confused with provider-based evaluation. |
| UX-020 | Copy/content | Loading and placeholders | Many strings use `...` instead of typographic ellipsis; some icons are emoji text. | Violates Web Interface Guidelines for loading/placeholder typography and icon consistency. | Examples: `frontend/src/App.tsx:296`, `528`, `1061`, `1433`, `4821`. | Use consistent ellipsis/ASCII policy or product copy standard; replace emoji with icons. | P3 | Loading/placeholders follow one product copy standard. |
