# Candidate Security And Privacy Audit

Safe static review only; no destructive testing performed.

| ID | Area | Finding | Evidence | Impact | Priority | Recommended fix / acceptance criteria |
|---|---|---|---|---|---|---|
| SEC-001 | Auth/session | Logout endpoint is a no-op and JWTs are not revoked after logout/password change/deactivation. | `AuthController.java:57-59`, `AuthService.java:240-251`, `frontend/src/services/api.ts:13-45`. | Stolen or old tokens remain usable until expiry. | P1 | Implement revocation/versioning or short-lived access tokens; old tokens fail after sensitive actions. |
| SEC-002 | Authorization | Backend role checks protect candidate APIs and services filter by owner for CV/applications/notifications/sessions. | `SecurityConfig.java:52-53`, `CandidateService.java:164-169`, `ApplicationService.java:149-155`, `AiInterviewService.java:708-713`. | Positive control; still needs API tests. | P2 | Add integration tests for IDOR attempts on candidate-owned resources. |
| SEC-003 | Public TTS stream | `/candidate/ai-interviews/speech/**` is permit-all; random short-lived ticket gates access. | `SecurityConfig.java:44`, `AiInterviewSpeechService.java:12-79`. | Token leakage allows temporary speech stream access. | P2 | Bind ticket to session/candidate or require auth plus token; log/expire one-time use if needed. |
| SEC-004 | CV upload | Backend validates PDF by extension and content-type only. | `CandidateService.java:337-351`. | Malicious/non-PDF content can bypass weak MIME checks. | P1 | Validate PDF magic/content, scan uploads, store private, reject mismatched content. |
| SEC-005 | Avatar upload | Backend validates content-type/size but does not verify image bytes or strip metadata. | `AuthService.java:300-312`. | Malicious image/polyglot or PII metadata risk. | P2 | Verify image decode, strip metadata, constrain dimensions. |
| SEC-006 | CV storage | Local uploads are present in workspace under `backend/uploads/cvs/...`; `.gitignore` status shows untracked upload dirs. | `git status --short` showed untracked `backend/uploads/cvs/...`; storage code loads local keys in `CandidateService.java:314-333`. | Real candidate PDFs can be accidentally shared/committed/backed up. | P1 | Ensure uploads are outside repo or ignored; purge sample/private files from source workspace. |
| SEC-007 | Secrets/config | Payment sandbox defaults include Momo access/secret-like values in `application.yml`. | `backend/src/main/resources/application.yml:99-104`. | Secret hygiene issue even if sandbox. | P1 | Move all secrets to env and use non-secret placeholders. |
| SEC-008 | CSRF | Backend is stateless JWT and CSRF disabled. | `SecurityConfig.java:29-31`; frontend stores token in localStorage. | Acceptable for bearer token APIs, but localStorage increases XSS token theft impact. | P2 | Harden XSS and consider httpOnly cookie/refresh-token strategy. |
| SEC-009 | XSS/content | Candidate-entered cover letter, profile text, transcripts, AI feedback render as React text, not raw HTML. | Rendering examples `frontend/src/App.tsx:3855-3860`, `5152-5156`; no `dangerouslySetInnerHTML` found in candidate paths. | Positive; needs regression tests. | P3 | Keep escaping by default; lint against raw HTML rendering. |
| SEC-010 | Job reports | `POST /jobs/{id}/reports` is not explicitly `@PreAuthorize`; security makes non-GET `/jobs/**` authenticated by default, but any authenticated role may reach unless service restricts. | `JobController.java:44-49`, `SecurityConfig.java:50-55`. | Employer/admin may be able to submit candidate-style reports unless service blocks. | P2 | Add explicit role policy for job reports and tests. |
| SEC-011 | Rate limiting | AI expensive actions have in-memory per-candidate rate limiting. Auth/register/forgot-password/login do not show rate limiting in reviewed code. | `AiInterviewRateLimiter.java:24-45`, auth controller `AuthController.java:32-55`. | Credential stuffing/password reset abuse risk. | P1 | Add auth endpoint rate limiting and lockout/backoff. |
| SEC-012 | AI data privacy | Interview transcripts and feedback are persisted and sent to external AI providers; application consent is UI-only and not persisted. | `ShopAiKeyClient.java:65-93`, `GladiaTranscriptionClient.java:31-103`, `frontend/src/App.tsx:539-544`. | Consent/audit gap for PII/audio/transcript processing. | P1 | Persist consent/policy version for AI processing and document retention. |
| SEC-013 | STT audio | Audio is uploaded to Gladia via URL-based flow; no local audio URL persistence seen except answer has `audio_url` field in schema. | `GladiaTranscriptionClient.java:31-71`, schema `V1__initial_schema.sql:301-303`. | Need privacy review of external provider retention. | P2 | Document provider retention and avoid storing audio unless needed. |
| SEC-014 | Error handling | Generic provider errors prevent exposing provider details in some flows; TTS failure includes up to 1,000 chars of provider error in exception message. | `ShopAiKeyClient.java:128-131`. | Provider error body may leak implementation details to client/logs. | P2 | Sanitize provider errors in user-facing API responses and logs. |
| SEC-015 | Database constraints | DB triggers enforce resume ownership for applications and AI answer question/session alignment. | `V1__initial_schema.sql:500-522`, `312-313`. | Positive defense-in-depth. | P3 | Keep DB-level invariants covered by migration tests. |

## Security Tests Needed

- IDOR tests for CV download/delete/default, CV builder, applications, notifications, AI sessions, AI answers, speech ticket creation.
- Auth throttling tests for login/register/forgot/reset.
- File upload adversarial tests for PDF/image polyglots, oversized files, wrong MIME, and malware policy.
- Token revocation tests after logout/password change/deactivation.
